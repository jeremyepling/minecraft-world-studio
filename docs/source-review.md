# MCPFabric engineering review

**Verdict.** Use stock MCPFabric for the first local building environment. It can convey intent, read blocks, capture the client and execute edits. Its command identities, per-cell plan repair and cancellation semantics affect which building operations are safe to delegate. Give WorldEdit work a consistent player identity and verify each operation against the world.

Reviewed 2026-11-24. The clean source checkout was Fabric tag `v0.10.0`, commit `54af200d845b4def8216167d2a0d41775e9b621d`. All implementation findings below are **confirmed in source** unless individually labeled. The reviewer inspected the release assets and actual Java and TypeScript code. Runtime evidence belongs to the installation, playtest and experiment records. A source-level limit is a contract to test, not a measured throughput result. ## Commands, WorldEdit and observation

- **Command identity.** `run_command` receives an entityless OP-level command source named mcpfabric, positioned at the Overworld spawn with zero rotation. This differs from a fabricated player entity. Server `set_block` and `fill_blocks` wrap vanilla commands in the requested dimension. On a client, `send_chat` handles a leading slash by passing the rest through the actual local player's connection under that player's permissions. It acknowledges sending the packet. For WorldEdit, use the local-player path for selection, clipboard and history, and read subsequent feedback and block states. Direct command success, registered slash syntax, history ownership and latency require live tests. [Command handler](https://github.com/denfry/mcpfabric/blob/54af200d845b4def8216167d2a0d41775e9b621d/src/main/java/dev/mcpfabric/handlers/CommandHandlers.java#L16) · [Command source](https://github.com/denfry/mcpfabric/blob/54af200d845b4def8216167d2a0d41775e9b621d/src/main/java/dev/mcpfabric/handlers/support/CommandRunner.java#L31) · [Client chat](https://github.com/denfry/mcpfabric/blob/54af200d845b4def8216167d2a0d41775e9b621d/src/client/java/dev/mcpfabric/client/handlers/ClientChatHandlers.java#L18) · [World writes](https://github.com/denfry/mcpfabric/blob/54af200d845b4def8216167d2a0d41775e9b621d/src/main/java/dev/mcpfabric/handlers/WorldHandlers.java#L205)
- **Survey coverage.** Region reads can return block states, optionally including air. The region scanner caps scan volume at 2²⁴ positions; results have a separate cap. Client perception supports batched loaded-position probes (up to 512 per request) and scanning loaded chunks within a radius of up to 12 chunks. The persistent map stores biome, sampled standable surface height at the chunk centre and selected block counts. `map_view` renders north-up text at one glyph per chunk. For a road profile, sample the footprint more densely. Slope, sightlines, protected regions and planned districts require derived or external data. [Region reads](https://github.com/denfry/mcpfabric/blob/54af200d845b4def8216167d2a0d41775e9b621d/src/main/java/dev/mcpfabric/handlers/WorldHandlers.java#L62) · [Perception](https://github.com/denfry/mcpfabric/blob/54af200d845b4def8216167d2a0d41775e9b621d/src/client/java/dev/mcpfabric/client/handlers/PerceptionHandlers.java#L84) · [Map store and rendering](https://github.com/denfry/mcpfabric/blob/54af200d845b4def8216167d2a0d41775e9b621d/mcp-server/src/agent/worldmap.ts)
- **Visuals.** Screenshot captures the client’s current main render target with GPU readback. The Java handler returns PNG bytes and dimensions. Node emits a native MCP image plus metadata and can overlay numbered visible entities. Capturing the current frame requires no player movement. Looking/turning changes the player view. No independent offscreen camera or isometric/cross-section renderer was found in the registered vision methods. Actual resolution and visual quality depend on the client. [Screenshot handler](https://github.com/denfry/mcpfabric/blob/54af200d845b4def8216167d2a0d41775e9b621d/src/client/java/dev/mcpfabric/client/handlers/VisionHandlers.java#L46) · [MCP image](https://github.com/denfry/mcpfabric/blob/54af200d845b4def8216167d2a0d41775e9b621d/mcp-server/src/index.ts#L80)
- **Chat.** Client chat can speak as the player, and `show_message` can display a private local AI message or action-bar progress. Player administration also includes a targeted message. Recent events can be polled. Upstream's unsolicited notification path specifically uses `claude/channel` and `notifications/claude/channel` over opt-in stdio. ## JavaScript and extension points

Each invocation creates a fresh QuickJS WebAssembly runtime for JavaScript. It supports async/await, standard language objects, promises, top-level return, JSON arguments through `mc.args`, `mc.sleep`, bounded console logging and bridge helpers. There is no guest Node module loader, filesystem, arbitrary network client or native timer API in the provided globals. Host-side Node does use the filesystem for SQLite and HTTP to reach the game. Installed game commands and mods retain their own capabilities. Calling a helper enforces its Zod schema and the game’s actual permissions; the host excludes supervised methods. Agent composites such as `build_plan` are outside the base bridge method set. [Sandbox prelude](https://github.com/denfry/mcpfabric/blob/54af200d845b4def8216167d2a0d41775e9b621d/mcp-server/src/script/sandbox.ts#L86) · [Script host validation](https://github.com/denfry/mcpfabric/blob/54af200d845b4def8216167d2a0d41775e9b621d/mcp-server/src/script/tools.ts#L23)

| --- | --- |
| Wall time | 60 s default, 1–300 s by tool argument |
| Guest heap / stack | 64 MiB / 512 KiB; these are guest limits, not a cap on the Node process |
| Bridge calls | 2,000 host calls per script; one VM can perform many calls within a single MCP invocation |
| Consecutive CPU | 5 s before the interrupt handler flags a busy computation |
| Program / output | 64,000 code characters; 16,000 log characters; 32,000 result characters; 8,000,000 JSON characters per host result to the guest |
| Args | Optional JSON-serializable value. The tool schema declares no separate maximum arg length. |

The host permits one active script per process and holds the agent body against concurrent jobs. Syntax/guest errors, bridge errors, timeouts and call limit produce run reports with calls, elapsed time and logs. The owner session closing aborts its script. Failure after bridge calls attempts movement/navigation/mining cleanup; committed block writes remain. No explicit `cancel_script` MCP tool is registered. The `save_skill` path compile-checks code before replacing the world-scoped SQLite entry; `run_skill` accepts fresh args. These executable skills are distinct from version-controlled agent instructions for architecture or art direction. **Extension decision.** Use commands, a checked-in generator or a saved program first. The Java router has public registration methods, but the Node tool list is static. No supported third-party plugin discovery, negotiated dynamic MCP tool schema, or documented stable Java extension contract was found. A companion can register its own Minecraft command and call the WorldEdit Java API in a bounded edit session if later requirements demand game-side previews, atomic conflict checks or independent rendering. A separate MCP server is unnecessary for this evaluation.
